Data Security

Encrypted per-guest keys, a pinned host fingerprint and host approval for every device. It has not yet been independently reviewed.

Last updated 12 November 2026

What protects you

  • Pairing uses a Noise XX handshake.
  • Audio and control packets are encrypted with ChaCha20-Poly1305, with a separate key for each guest.
  • Fingerprint pinning: the QR code carries a fingerprint of the host's identity, so a guest refuses to talk to an impostor and never sends its one-time token to the wrong device.
  • Host approval: every device must be approved on the host before it hears anything.
  • Single-use tokens: each join uses a fresh token.
  • Local network only: no relay servers.
  • Wi-Fi in the QR is opt-in: it is off by default, and the host screen warns that anyone who sees the QR can read the Wi-Fi password in it. Use a hotspot password you do not reuse elsewhere.

Known limitations

  • The design has not been independently audited.
  • The host's identity key is stored as a plain file in its data folder.
  • Nothing protects against someone who can already run code on the host or guest device.
  • Anyone on your network can see that Roundelay traffic exists, though not its content.

What you can do

Use a network you trust, approve only devices you recognise, keep the app and your operating system up to date, and report anything suspicious through the private advisory form.
