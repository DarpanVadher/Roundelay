Data Breach Procedure

Since the project holds no user data, a breach would mean a vulnerability in the software or its release pipeline. This is how we handle one.

Last updated 12 November 2026

Reporting

Report privately using the GitHub security advisory form, not a public issue. Include what you found, how to reproduce it and what an attacker could do. We aim to acknowledge within a few days.

What we do

  1. Confirm and assess the problem, and what it could expose.
  2. Fix it on the main branch (there are no supported release branches yet) and ship a new release.
  3. Publish a GitHub security advisory describing the issue, who is affected and how to update, crediting the reporter if they wish.
  4. If a release file or this website were compromised, withdraw the affected downloads and say so in the release notes and on this site.

Notifying you

We have no list of users to contact, so notices are public: the advisory, release notes and this website. If personal data of yours were ever involved, we would tell the people affected and any required authority within the legal deadlines, which is 72 hours to a supervisory authority under the GDPR where it applies.
